# 项目开发历程

## 起点

项目最早是一个面向 Feishu / Lark 的本地 Codex 桥接层，目标很直接：让消息驱动 Codex，减少在终端和聊天工具之间来回切换的成本。

## 线程稳定阶段

第一批核心工作集中在线程绑定、线程切换、卡片上下文恢复和工作区状态展示上，重点是让消息始终落在正确的线程里，不因为分页、切换或重启丢上下文。

## 恢复与超时阶段

之后的修复重点转到运行时恢复、RPC 超时和失败提示上。这个阶段解决的是“看起来卡住了、实际没回”的问题，让用户能看到明确的阻塞原因和恢复建议。

## 移动端体验阶段

后续优化集中在 Feishu 端展示：压缩卡片内容、改进普通回复样式、减少 quoted reply 噪音、让线程切换后的反馈更轻更清晰。

## MCP 与审批阶段

最后补上 MCP 工具审批、`getnote` 一类授权流、线程消息预览和审批卡片交互，适配更完整的真实使用场景。

## 迁移到 `codex-lark`

现在这个仓库作为对外发布版本，保留了 `codex-im` 的核心代码演进成果，并以 `codex-lark` 作为新的发布名与仓库名。
